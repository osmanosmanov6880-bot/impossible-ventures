# IMPOSSIBLE VENTURES — Experiment Lab v0.7

**Статус:** исходный код исследовательской альфа-версии. Не рекламная сеть, не платёжная платформа, не готовый коммерческий SaaS. Код и прошедшие тесты не подтверждают законность обработки данных, качество трафика, эффективность рекламы или готовность к массовому запуску.

## Что работает

Experiment Lab превращает идею интерактивной рекламы в **проверяемый эксперимент**:

1. Оператор создаёт черновик A/B-эксперимента для одной аудитории и одного предложения.
2. **A** — прямой рекламный текст и CTA.
3. **B** — альтернативный сюжет, два авторских выбора и два разных последствия. CTA появляется после выбора. Текст составляется оператором, а не моделью на лету.
4. Оператор запускает эксперимент и получает ссылку /experiments/?id=IDENTIFIER.
5. Посетитель может открыть **неизмеряемую локальную демоверсию без регистрации**. Результаты демо не записываются.
6. Для живого исследования посетитель сам ставит галочку согласия, после чего сервер случайно назначает A или B с вероятностью 50% на каждый запрос; точная пропорция 50/50 не гарантируется.
7. Техническое начало измеряемой сессии и первое нажатие CTA сохраняются в агрегированной SQLite-статистике. Повторный клик по тому же токену не увеличивает показатель.
8. Оператор видит реальные технические старты, клики, наблюдаемые доли отклика и интервалы Уилсона. Он может приостановить, возобновить или завершить тест, а также скачать CSV без персональных данных посетителей.

**Важно:** начало сессии — не гарантированный просмотр реальным человеком. Нажатие CTA — не завершённая заявка, оплаченный заказ или выручка. Нет интеграции с Google Ads, Meta или другими рекламными сетями. Заявки Pilot Studio не атрибутируются автоматически к экспериментальным сессиям.

## Запуск локально

Node.js 22+, без дополнительных npm-зависимостей для работы сервера.

PowerShell (Windows):

~~~powershell
git clone https://github.com/osmanosmanov6880-bot/impossible-ventures.git
cd impossible-ventures
$env:OPERATOR_TOKEN = node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('base64url'))"
npm start
~~~

Bash:

~~~bash
export OPERATOR_TOKEN="$(node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('base64url'))")"
npm start
~~~

- Публичная страница: http://localhost:3000/experiments/
- Оператор экспериментов: http://localhost:3000/experiments/operator/
- Студия коммерческих пилотов: http://localhost:3000/pilot/
- Кабинет заявок: http://localhost:3000/pilot/operator/
- Кооперативная рекламная игра: http://localhost:3000/apps/dead-drop/

Токен оператора не сохраняется в базе данных и в браузерном хранилище. При закрытии вкладки его нужно вводить снова. Для реального размещения нужны секреты в менеджере секретов и защищённый HTTPS-домен. Никогда не публикуйте токен в коде или GitHub.

## API

Операторские операции требуют HTTP-заголовка Authorization: Bearer OPERATOR_TOKEN.

- POST /api/v1/operator/experiments — создаёт черновик. JSON-поля: title, audience, offer, hypothesis, controlHeadline, controlBody, variantHeadline, variantBody, decisionPrompt, choiceOneLabel, choiceOneReveal, choiceTwoLabel, choiceTwoReveal, ctaLabel.
- GET /api/v1/operator/experiments — максимум 100 последних кампаний с настройками и агрегированными показателями за 90 календарных дней.
- POST /api/v1/operator/experiments/:id/status — переход между статусами draft, running, paused, completed. Возможные переходы: draft→running/completed, running→paused/completed, paused→running/completed. Завершённый эксперимент нельзя восстановить.

Публичные операции:

- GET /api/v1/experiments — только запущенные кампании без внутренних гипотез и деталей неопубликованных креативов.
- POST /api/v1/experiments/:id/sessions — JSON: { "consent": true }. Возвращает случайно назначенный вариант и секрет временной анонимной сессии. B содержит сценарные ветви.
- POST /api/v1/experiments/:id/sessions/:sessionId/cta — Authorization: Bearer ANONYMOUS_SESSION_TOKEN. Учитывается только первое CTA-событие; повтор выдаёт recorded: false.

Выбранный пользователем сюжет B **не отправляется на сервер** и остаётся состоянием текущей вкладки.

## Данные и приватность

- Таблица ab_sessions хранит случайный ID сессии, ID эксперимента, назначенный вариант, SHA-256-хеш случайного токена, время начала и флаг CTA. В ней нет имён, email, IP-адресов, user-agent или маркетингового профиля.
- Клиентский токен находится **только в памяти вкладки** и теряется при перезагрузке. Это ограничивает возможности слежения, но позволяет одному посетителю начать несколько сессий. Количество сессий **не равно числу уникальных пользователей**.
- Таблица ab_daily хранит обезличенные суточные агрегаты по эксперименту и версии.
- Индивидуальные сессии удаляются после 7 дней, агрегаты за пределами последних 90 календарных дней удаляются. Очистка при старте, затем ежечасно и при чтении оператором. Физическое стирание из резервных копий не гарантируется.
- IP-адрес временно используется **в оперативной памяти** для ограничения создания сессий (20/час/IP на одном сервере). Прокси и инфраструктурные журналы могут отдельно записывать IP. Их обработка и хранение требуют проверки.
- Система использует серверную проверку полей, лимит JSON-body 16 КиБ, криптографически случайные токены, проверку хешей, статический allowlist и строгую CSP. Это не заменяет ботовый фильтр, распределённый rate-limit, WAF, MFA, RBAC, аудит уязвимостей или GDPR/ePrivacy-оценку.
- Оператор использует общий серверный секрет. Это не персональные аккаунты сотрудников и не многоарендная изоляция.

**Не подключайте коммерческий публичный трафик до HTTPS, проверки статуса юридического оператора данных, процедур хранения и удаления, безопасности, антифрода и законности рекламных заявлений.**

## Значение метрик

| Показатель | Метод | Что нельзя заключать |
|---|---|---|
| Технические сессии | Количество анонимных подтверждённых назначений A/B | Не уникальные люди и не реальные закупленные показы |
| CTA | Уникальное для токена сессии нажатие | Не лид, покупка, оплата |
| Доля CTA | CTA / сессии отдельно для A и B | Не прогноз продаж |
| Разница | 100 × (доля B − доля A), процентные пункты | Не доказательство прироста |
| 95% Wilson | Интервал биномиальной доли в каждой группе | Не тест значимости разницы между A и B |
| Проверка дисбаланса | При N≥100, если разница числа сессий > 3√N | Грубый сигнал о распределении, не гарантия случайности |

Зафиксируйте критерий успеха и длительность эксперимента **до** запуска. Не объявляйте победу по малой выборке, при повторных просмотрах результатов или без проверки качества трафика. Для реального сравнения эффективности нужны предварительный расчёт мощности, независимая проверка целевого события и соблюдение правил статистического анализа.
