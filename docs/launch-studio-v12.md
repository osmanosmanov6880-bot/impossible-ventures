# IMPOSSIBLE VENTURES — Five-WAVE Launch Studio v1.2 beta

Дата: 22 октября 2026. Статус: программная бета-версия собственного первого канала размещения интерактивного креатива на том же хосте. Не международная рекламная сеть, не оплаченный трафик и не подтверждённые продажи.

## Какие пять WAVE выполнены

| WAVE | Рабочий результат | Файлы |
|---|---|---|
| 11 — Controlled Launch | Владелец запускает неизменяемую копию **одобренной** кампании, отдельно активирует её, ставит на паузу, возобновляет или навсегда закрывает | `services/commercial/launches.mjs`, `apps/commercial/app.js` |
| 12 — Seven First-Party Stories | Страница `/play/?id=<launchId>` с реальными интерактивными переходами для семи творческих направлений; русская, английская и китайская локализации, поддержка мобильного экрана | `apps/launch/{index.html,style.css,app.mjs,story.mjs}` |
| 13 — Consent and Event Accounting | Отдельное добровольное согласие перед выдачей случайного хешируемого ключа; учёт запуска, завершения и CTA с защитой от двойного зачёта, лимитом создания сессий и сроками хранения | `services/commercial/launches.mjs` |
| 14 — CTA to Lead | Одноразовая криптографическая квитанция CTA, а затем **отдельное** согласие контактной формы Pilot Studio, атомарная привязка заявки к конкретной публикации, запрет повторного использования | `services/pilot-studio/pilots.mjs`, `apps/pilot-studio/app.js` |
| 15 — Owner Analytics and Release | Полный кабинет оператора: статусы, ссылки, метрики технических событий, настоящие отправленные формы и ручная квалификация, мини-графики, CSV без личных данных, удаление вместе с организацией | `apps/commercial/{index.html,app.js,style.css}`, `services/commercial/workspaces.mjs` |

## Сценарий: от редактора до настоящей отправленной заявки

1. Запустите Node-сервер и откройте `/commercial/`. Создайте организацию с настроенным системным секретом `OPERATOR_TOKEN` или войдите по своему токену владельца. Не публикуйте ключ в чате, ссылках или репозитории.
2. Создайте и сохраните рекламный макет. Владелец должен проверить законность и доказательства и нажать «Одобрить». Сохранённая версия после одобрения не редактируется.
3. В Launch Studio выберите одобренную кампанию → «Создать публикуемую версию» → «Опубликовать». До активации публичное API возвращает 404.
4. Откройте `/play/?id=<id>`; посетитель проходит три интерактивные сцены с выбором из двух вариантов. Для участия **не требуется** регистрация, согласие на аналитику и предоставление контактов. Варианты выбора хранятся в памяти вкладки и не передаются API.
5. При отдельном согласии посетителя сервер выдаёт случайный технический ключ и засчитывает только запуск сессии, сигнал завершения и максимум один CTA для этой сессии. Это не просмотры и не уникальные люди.
6. Если посетитель нажимает CTA, в памяти этой вкладки sessionStorage сохраняется одноразовая квитанция на срок не более 7 дней. Переход в `/pilot/` не отправляет данные о личности автоматически.
7. Только когда посетитель отдельно согласился на контакт и отправил форму, Pilot Studio атомарно привязывает её к квитанции. Оператор вручную отмечает статус заявки. Принятый коммерческий документ и статус won не доказывают оплату.
8. Кабинет Launch Studio показывает реальные технические события, количественные формы и ручную квалификацию; отчёт CSV не содержит имён или адресов. Публикацию можно поставить на паузу; после архивации исходной кампании она также недоступна.

## Первичная архитектура API

| Метод и URL | Кто имеет право | Назначение |
|---|---|---|
| `GET /api/v1/workspaces/{ws}/launches` | owner/editor/viewer | публикации и агрегированные данные организации |
| `POST /api/v1/workspaces/{ws}/launches` | owner | создание снимка утверждённого креатива |
| `POST /api/v1/workspaces/{ws}/launches/{id}/activate` | owner | включение публичной страницы |
| `POST /api/v1/workspaces/{ws}/launches/{id}/pause` | owner | остановка без удаления |
| `POST /api/v1/workspaces/{ws}/launches/{id}/resume` | owner | возобновление при действующем одобрении кампании |
| `POST /api/v1/workspaces/{ws}/launches/{id}/retire` | owner | необратимое завершение |
| `GET /api/v1/workspaces/{ws}/launches/{id}/metrics` | owner/editor/viewer | реальные счётчики и границы интерпретации |
| `GET /api/v1/workspaces/{ws}/launches/{id}/report.csv` | owner/editor/viewer | скачивание отчёта с Authorization Bearer |
| `GET /api/v1/launches/{id}` | публично, только когда активна | обезличенный опубликованный текст, без аудитории и токенов |
| `POST /api/v1/launches/{id}/sessions` | явное `{consent:true}` | создание случайной сессии; ключ возвращается один раз |
| `POST /api/v1/launches/{id}/sessions/{sid}/complete` | токен сессии | однократный сигнал завершения истории |
| `POST /api/v1/launches/{id}/sessions/{sid}/cta` | токен сессии и завершённая история | однократный CTA и подтверждение для будущей заявки |
| `POST /api/v1/pilots` | отдельное согласие на контакт | необязательная форма с защищённой квитанцией `launchAttribution` |

## Безопасность и ограничения

- Защита публикации: только owner, исходная кампания в статусе approved, уникальная незавершённая версия на кампанию, однонаправленные переходы статусов, неизменяемый JSON-снимок исходного текста.
- Периметр: отдельные workspace ID, отдельные capability-токены с хешированием/сроком истечения; API не выдаёт контакты и пользовательские описания аудитории на публичной странице.
- Встраивание: разрешено **только в iframe на этом же origin** (`X-Frame-Options: SAMEORIGIN`, `CSP: frame-ancestors 'self'`). Для иных доменов требуется новая проверка безопасности и отдельная настройка, а не обход политики.
- Аналитика: явный opt-in, без сторонних пикселей и cookies; хеши ключей, агрегация раз в календарные сутки; сырые сессии максимум 7 дней, сводные данные до 90 дней.
- CTA квитанция: 24 криптографических случайных байта, сохранённый сервером SHA-256, одноразовое атомарное предъявление, истечение через 7 дней. Нельзя привязать одновременно атрибуцию Experiment Lab и Launch Studio к одной заявке.
- При удалении заявки количественная оценка связанных форм уменьшается; повторное использование прежней квитанции остаётся запрещённым. Удаление организации очищает публикации, обезличенные сессии и суточные агрегаты из активной SQLite и убирает внешний указатель `launch_id` из отдельно согласованных глобальных форм.
- Экспорт организации включает соответствующие публикации и агрегированные события, но не открывает ключи участников. Отчёт CSV содержит только числовые агрегаты и никакой контактной информации.
- До производственного рекламного масштаба нужны реальные проверки владения доменами, SSO/MFA, независимая антифрод-система, соблюдение законодательства рекламы и приватности, обработка реальных рекламных сетей и транзакционная платёжная интеграция.

## Как запустить и проверить

Node.js 22+:

    npm run check
    npm start

Полные браузерные тесты Chromium:

    npm install --no-save --package-lock=false playwright@1.55.0
    npx playwright install chromium
    node --test services/dead-drop/browser.test.mjs

Первый запуск с новым модулем создаёт таблицы `commercial_launches`, `launch_sessions`, `launch_daily` и добавляет отсутствующую колонку `pilot_leads.launch_id`; существующие заявки и A/B-эксперименты не удаляются. **Перед обновлением рабочей базы сделайте резервную копию** согласно `docs/operations-runbook.md`. Отдельно сохраняйте удалённые резервные копии по политике вашей организации.

Static preview (`python3 scripts/build_static_preview.py`) намеренно **не включает** активные страницы `/play/` и операторские API: их работа требует полноценного Node-хоста и живой SQLite. Статический деморежим по-прежнему доступен для локального редактирования творческих идей без сохранения на сервер.

## Что пока не реализовано

Размещение в Google/Meta/Яндекс, внешний рекламный обмен, DSP/SSP/RTB, посторонние домены iframe, платёжный провайдер, факт получения денег, безопасный антибот без ошибок, подсчёт уникальных реальных людей, статистически подтверждённый рекламный прирост. Технические события без независимого источника нельзя продавать как настоящие показы.
